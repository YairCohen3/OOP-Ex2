# SmartClass: הוראות הרצה ופריסה

**האתר החי:** https://oop-ex2-production.up.railway.app
התיעוד המלא (באנגלית) נמצא ב-[README.md](README.md) ובתיקיית [Documents](Documents).

## הרצה במחשב

מתוך תיקיית הפרויקט (למשל ב-Terminal של PyCharm):

```bash
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

פותחים בדפדפן: http://127.0.0.1:8000

## משתני סביבה

| משתנה | למה |
|---|---|
| `GEMINI_API_KEY` | חובה לפיצ'רי ה-AI: ספירת אנשים, סיכום וידאו, בדיקת מטלות והשוואה. בלי מפתח המערכת מציגה "לא מוגדר" ולא ממציאה תוצאות. |
| `GEMINI_MODEL` | רשות. ברירת מחדל: `gemini-3.5-flash` |
| `GEMINI_FALLBACK_MODEL` | רשות. מודל גיבוי כשהמודל הראשי עמוס. ברירת מחדל: `gemini-3.5-flash-lite` |
| `SMARTCLASS_DATA_DIR` | תיקיית הנתונים (מסד הנתונים, קבצים שהועלו, דוחות Excel). ב-Railway: נתיב ה-Volume, למשל `/data` |
| `SMARTCLASS_QR_SECRET` | מפתח קבוע ל-QR הדינמי. חובה אם יש יותר משרת אחד. |

ב-Windows PowerShell:

```powershell
$env:GEMINI_API_KEY="..."
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

את המפתח לא שמים בקוד ולא ב-GitHub.

## הרצת הבדיקות

```bash
python -m pytest -v
```

הבדיקות רצות על מסד נתונים זמני וריק, ולא נוגעות בנתונים האמיתיים.

## זרימת הנוכחות (הפיצ'ר המרכזי)

1. המרצה פותח הרצאה חדשה. ה-QR הדינמי נפתח על כל המסך ומתחלף כל 10 שניות. אי אפשר לצאת ממנו עד שלוחצים "סיום רישום הנוכחות".
2. הסטודנטים סורקים מתוך החשבון שלהם בטלפון.
3. "סיום רישום הנוכחות" (SESSION END) נועל את הסריקות. אם מישהו איחר, אפשר לפתוח את הרישום מחדש.
4. מצלמים את הכיתה (במחשב, או בטלפון דרך QR הצילום), ו-Gemini סופר את האנשים. אפשר לתקן את הספירה ידנית. אם ה-AI נכשל, המערכת מבקשת ספירה ידנית.
5. הצלבה:
   - יותר רישומים מאנשים בתמונה: אזהרה ושלוש אפשרויות: (א) התחלת נוכחות מחדש, (ב) צילום חוזר, (ג) אישור וייצוא.
   - אנשים בתמונה ≥ רישומים: הרשימה תקינה.
6. אחרי האישור נוצר קובץ Excel (שם, מייל מוסדי, זמן, סטטוס, בלי ת"ז), וחלק הנוכחות מתכווץ לשורה אחת עם הקישור להורדה. הקובץ זמין גם בהרצאות שהסתיימו.

## מטלות וציונים

- הסטודנט לוחץ על מטלה ומצרף עד 10 קבצים בחלון קופץ.
- Gemini בודק את העבודה וממליץ על ציון. הציון והסקירה מוצגים **רק למרצה**.
- הסטודנט רואה "ממתין לציון המרצה" עד שהמרצה מאשר את הציון או מעדכן אותו. רק אז הוא רואה את הציון ואת המשוב.
- פורום המשוב מציג משוב בלי שמות ובלי ציונים, רק על הגשות שהציון שלהן אושר.

## צילום מהטלפון ברשת מקומית

1. חברו את המחשב והטלפון לאותה רשת Wi-Fi.
2. ב-Windows הריצו `ipconfig` ומצאו את ה-IPv4 Address (למשל 192.168.1.27).
3. במסך ההרצאה, אם הכתובת שהוצעה לא מתאימה, הזינו `http://192.168.1.27:8000`.
4. סרקו בטלפון את ה-QR שבחלק "צילום הכיתה", צלמו ושלחו.
5. אם הטלפון לא מצליח להתחבר, אפשרו את פורט 8000 ב-Windows Firewall.

QR הנוכחות ו-QR הצילום הם שני קודים שונים.

## טיימרים ורענון

- קוד הכניסה (OTP) תקף 120 שניות, עם שעון וכפתור לשליחה מחדש.
- QR הנוכחות מתחלף כל 10 שניות, עם 2 שניות חסד.
- הנוכחות, הפורום והסקרים מתעדכנים כל 5 שניות.

## מגבלות דמו ידועות

- קוד הכניסה מוצג על המסך לצורך הדמו ולא נשלח במייל.
- רשימת המשתמשים המורשים מוגדרת בקוד (`AUTH_USERS` ב-`main.py`).
- ההרשאות מבוססות על המייל שנשלח בכל בקשה, בלי token. מתאים לדמו בלבד.
- העדכונים הם polling כל 5 שניות, לא WebSocket.
- תמונת הכיתה לא נשמרת. נשמרים רק מספר האנשים ושיטת הספירה.
- סריקת QR במצלמת הטלפון דורשת HTTPS (עובד ב-Railway). ברשת מקומית אפשר להעלות קובץ.
- קישור ישיר להקלטה נתמך רק ליוטיוב ציבורי. הקלטות Zoom או Classroom מורידים ומעלים כקובץ (עד 500MB).

## פריסה ב-Railway

1. Push ל-GitHub, ו-Railway פורס אוטומטית.
2. מגדירים Volume ומכוונים אליו את `SMARTCLASS_DATA_DIR`. בלי זה הנתונים נמחקים בכל פריסה.
3. מגדירים `GEMINI_API_KEY` ב-Variables.
4. אחרי הפריסה לוחצים Ctrl+F5 בדפדפן כדי לקבל את הגרסה העדכנית.
